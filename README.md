# FinnyPet — «Питомец Финни»

Мобильное приложение для формирования базовых финансовых навыков у детей 7–11 лет.

**Целевая аудитория:** дети 7–11 лет, начинающие знакомство с управлением карманными деньгами.  
**Платформа:** Android 8.0+ (API 26+).  
**Стек:** Kotlin (нативная разработка) / Jetpack Compose, Room, DataStore.  
**Статус:** функциональный прототип, подготовленный к размещению в RuStore.

## Назначение

«Питомец Финни» — игровой сервис, в котором ребёнок создаёт виртуального питомца, получает игровую валюту, планирует её распределение на обязательные и необязательные расходы и накопления, выполняет задания по финансовой грамотности. Состояние и развитие питомца зависят от финансовых решений пользователя: обеспечены ли обязательные расходы, соответствовали ли фактические траты плану, удалось ли отложить средства на цель.

## Образовательная цель

Сформировать у ребёнка базовые навыки управления личными финансами в игровой форме:

- понимание ограниченности ресурсов;
- различение обязательных и необязательных расходов;
- планирование простых покупок;
- постановка краткосрочной финансовой цели и регулярные накопления;
- оценка собственных финансовых решений и их последствий.

### Шаги запуска

1. **Клонировать репозиторий:**

```bash
git clone https://github.com/Alena-aaa/FinnyPet.git
cd FinnyPet
```

2. **Открыть проект в Android Studio:**
   - File → Open → выбрать папку проекта.
   - Дождаться синхронизации Gradle.

3. **Собрать и запустить:**

```bash
./gradlew assembleDebug
```

Или нажать **Run** (зелёный треугольник) в Android Studio.

4. **Запуск на физическом устройстве:**
   - Включить режим разработчика и отладку по USB.
   - Подключить устройство, выбрать его в списке целевых устройств.
   - Нажать **Run**.

### Стек

| Слой | Технология |
|---|---|
| Язык | Kotlin |
| UI | Jetpack Compose (Material 3) |
| Навигация | Navigation Compose |
| Хранение данных | Room (SQLite) + DataStore (Preferences) |
| Асинхронность | Coroutines + Flow |
| DI | Hilt (или ручной DI) |
| Тестирование | JUnit, Espresso, Compose Testing |

### Архитектура

Приложение построено по принципам **чистой архитектуры** с разделением на три слоя:

1. **Data layer** — источники данных (Room, DataStore), репозитории. Отвечает за сохранение и извлечение профиля, баланса, покупок, накоплений, прогресса.
2. **Domain layer** — бизнес-логика, не зависящая от Android:
   - расчёт доступного баланса и накоплений;
   - проверка лимитов бюджета;
   - изменение состояния и стадии питомца;
   - формирование обратной связи.
3. **UI layer** — экраны на Jetpack Compose, ViewModel. Отображает состояние, принимает пользовательские действия, передаёт их в domain layer.

**Разделение учебного контента и логики:** задания, товары и цели описаны в отдельных data-классах (или JSON-файлах в `assets/`). Добавление нового задания не требует изменения кода интерфейса или бизнес-логики.

### Хранение данных

- **Профиль, баланс, покупки, накопления, прогресс** — Room (локальная база данных SQLite).
- **Настройки (звук, анимации, демонстрационный режим)** — DataStore Preferences.
- **Учебный контент** — статические данные в коде или `assets/content.json`.

Все данные хранятся **только на устройстве**.

### Задания

## Формулы расчёта баланса, наград, состояния и роста питомца

### Баланс

Доступный баланс = Стартовый бюджет + Σ(Награды за задания) + Σ(Периодический доход) − Σ(Покупки) − Σ(Переводы в накопления) + Σ(Снятия с накоплений)

**Правило:** баланс не может быть отрицательным. При попытке покупки при недостатке средств приложение показывает, чего не хватает, и предлагает альтернативы (отложить покупку, выполнить задание).

### Награды

| Источник | Формула / правило |
|---|---|
| Выполнение задания | Фиксированная сумма из `FinancialTask.reward` (10–30 единиц) |
| Ежедневный вход | +10 единиц (один раз в календарный день) |
| Завершение периода с выполненным планом | Бонус +20 единиц |
| Пополнение накоплений | Без прямой награды, но влияет на прогресс питомца |

### Состояние питомца

Настроение = f(Обязательные расходы, Соответствие плану, Регулярность накоплений)

**Правила:**

| Условие | Изменение настроения |
|---|---|
| Все обязательные расходы оплачены | Настроение не ухудшается |
| Факт ≤ План по всем категориям | +1 к настроению (до максимума) |
| Регулярное пополнение накоплений (≥ 3 периода подряд) | +1 к настроению |
| Пропущены обязательные расходы | −1 к настроению (временное, восстановимое) |
| Превышен план по необязательным расходам | −1 к настроению (временное) |

**Важно:** настроение — обратимая характеристика. Оно не может стать «критическим» или привести к необратимым последствиям. После корректировки бюджета или выполнения задания настроение восстанавливается.

### Рост питомца (стадии развития)

Стадия = f(Количество завершённых периодов, Доля выполненных планов, Регулярность накоплений)

| Стадия | Условие перехода |
|---|---|
| Яйцо → Детёныш | Завершён 1 игровой период |
| Детёныш → Молодой | Завершено 2 периода, план выполнен хотя бы в 1 |
| Молодой → Взрослый | Завершено 4 периода, план выполнен в 3 из 4, накопления регулярны |

Развитие зависит от **совокупности решений за несколько периодов**, а не от одного действия. Ребёнку показывается краткое объяснение причины изменения состояния.

## Карта образовательного контента

| Тема | Навык | Сценарий | Правильная логика | Объяснение для ребёнка |
|---|---|---|---|---|
| **Планирование бюджета** | Различать обязательные и необязательные расходы; планировать простые покупки | Питомец хочет новую игрушку, но нужно купить еду. У ребёнка ограниченная сумма | Сначала обеспечить обязательные расходы (еда), затем выделить часть на игрушку, остальное — в накопления | «Сначала мы заботимся о том, что действительно нужно питомцу. Игрушка — это желаемое, её можно купить позже или отложить на неё деньги» |
| **Формирование сбережений** | Ставить краткосрочную финансовую цель и регулярно откладывать часть средств | Питомец мечтает о домике. Он стоит 100 монет. Ребёнок получает 30 монет за период | Откладывать по 20–25 монет каждый период, не тратить всё на необязательные расходы | «Если каждый раз откладывать хотя бы немного, цель становится ближе.» |
| **Платежи и покупки** | Принимать решения в условиях ограниченного бюджета; оценивать финансовые решения | В магазине есть три товара: еда (обязательно), игрушка (желательно), украшение (необязательно). Сумма ограничена | Купить еду, затем выбрать что-то одно из оставшихся, если хватает средств | «Нельзя купить всё сразу. Нужно выбрать, что важнее сейчас, а что можно отложить» |
| **Непредвиденные расходы** | Оценивать собственные финансовые решения и объяснять, к чему они привели | Питомец заболел, нужно лечение. Это обязательный расход, но он не был запланирован | Использовать накопления или скорректировать план на следующий период | «Иногда случается то, что мы не планировали. Хорошо, что у нас есть накопления — они помогают справиться» |

**Всего заданий:** минимум 6 (по 2 на каждую из 3 обязательных тем).  
**Формат:** игровая ситуация с выбором и последствиями, не ограничивается выбором ответа из предложенных вариантов. После ответа — короткое объяснение независимо от правильности.

## Обоснование UX/UI и доступности

### Принципы UX/UI

1. **Короткие фразы и простые слова.** Сложные термины сопровождаются объяснением. Основной текст — не менее 16 sp.
2. **Крупные интерактивные элементы.** Рекомендуемый минимум — 48 × 48 dp. Кнопки и элементы управления удобны для нажатия детьми.
3. **Один экран — одно действие.** Ребёнок понимает, что можно сделать и как перейти к следующему шагу, без длинной инструкции.
4. **Цвет не является единственным способом передачи информации.** Ошибки, успех, категории расходов и состояние питомца обозначаются также текстом, иконками и анимацией.
5. **Последовательная навигация.** Кнопка возврата расположена единообразно на всех экранах. Контраст текста и фона соответствует рекомендациям Android по доступности.
6. **Звуки и анимации можно отключить.** Критически важная информация не передаётся только звуком.
7. **Подтверждение важных действий.** Удаление данных, сброс профиля и другие действия, заметно меняющие прогресс, требуют подтверждения.

### Доступность

- Поддержка системного увеличения шрифта.
- Контент доступен для скринридеров (TalkBack).
- Альтернативные текстовые описания для изображений питомца и иконок.
- Возможность управления без точных жестов (крупные зоны нажатия).

### Цветовая схема

- Мягкие, неагрессивные цвета.
- Высокий контраст для текста.
- Питомец и его состояние визуально различимы даже при монохромном отображении (используются формы и выражения).

## Разрешения Android, данные, удаление профиля

### Разрешения

**Приложение не запрашивает разрешения Android для обязательного сценария.**

Камера, микрофон, геолокация, контакты, Bluetooth и другие аппаратные разрешения не используются. Если в будущем потребуется сетевой доступ для обновления контента, будет запрошено только разрешение `INTERNET`, и приложение будет работать без постоянного подключения к сети.

### Собираемые данные

- **Персональные данные не собираются.** Игровое имя и внешний вид питомца — условные, не привязаны к личности ребёнка.
- **Реальные платёжные данные не запрашиваются.**
- **Аккаунт не создаётся.** Работа в гостевом режиме.

### Удаление профиля

Удаление локального профиля доступно в **разделе для взрослого** (защищён барьером: удержание кнопки или арифметический пример). При удалении:

1. Показывается предупреждение о потере прогресса.
2. Требуется подтверждение.
3. Все локальные данные (профиль, баланс, покупки, накопления, прогресс) удаляются безвозвратно.
4. Приложение возвращается к экрану первого запуска.

**Сброс тестового профиля** в демонстрационном режиме также доступен в разделе для взрослого.

## Ограничения и план развития

### Известные ограничения прототипа

1. **Серверная часть не реализована.** Все данные хранятся локально. Синхронизация между устройствами отсутствует.
2. **Публикация в RuStore не выполнена.** Подготовлен подписанный APK, но размещение отложено до завершения конкурса.
3. **Раздел для взрослого минимален.** Полноценный удалённый родительский контроль не реализован.
4. **Контент ограничен обязательным минимумом.** 6 заданий, 8 товаров, 3 цели.
5. **iOS-версия отсутствует.** Адаптация под iOS не входит в конкурсный минимум.

### План дальнейшего развития

1. **Расширение контента:** добавление новых заданий, товаров и целей без изменения логики приложения.
2. **Облачная синхронизация:** опциональная, с явным согласием законного представителя.
3. **Раздел для взрослого:** расширенная статистика прогресса, возможность начисления дополнительных баллов.
4. **Публикация в RuStore:** подготовка карточки приложения (иконка 512×512, скриншоты, описание, возрастная маркировка).
5. **Адаптация под планшеты и альбомную ориентацию.**
6. **Локализация:** при необходимости — дополнительные языки.
